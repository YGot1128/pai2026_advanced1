# ACT スクラッチ実装 × ALOHA シミュレーション

Physical AI 応用1講座 最終課題のリポジトリです。

模倣学習の手法 **ACT (Action Chunking Transformer)** を素の PyTorch でスクラッチ実装し、ALOHA 双腕ロボットのシミュレータ上でキューブの受け渡しタスク（transfer cube）を実行します。

> **進捗状況**: 開発中です。ACT をスクラッチ実装して学習・評価し、成功率 **72%（36/50）** を得ました（[結果: ACT](#結果-act)）。現在は追加実験と、比較用の Diffusion / Flow Matching ヘッドの実装を進めています（[進捗](#進捗)を参照）。

---

## 概要

| 項目 | 内容 |
|---|---|
| タスク | **transfer cube**: 右腕でキューブを掴み、左腕に受け渡す |
| 手法 | ACT（CVAE + Transformer encoder-decoder + action chunking） |
| データ | [`lerobot/aloha_sim_transfer_cube_human`](https://huggingface.co/datasets/lerobot/aloha_sim_transfer_cube_human)（人間による遠隔操作のデモ 50本 / 50fps / 1本400フレーム） |
| シミュレータ | [gym-aloha](https://github.com/huggingface/gym-aloha)（MuJoCo / dm_control） |
| 観測 | 上方カメラ画像 480×640 RGB + 両腕の関節角 14次元 |
| 行動 | 両腕の目標関節角 14次元（各腕: 6関節 + グリッパー） |
| 評価指標 | シミュレータ上でのタスク成功率（reward = 4 に到達したエピソードの割合） |

### この課題のポイント

- **ポリシーをスクラッチで実装**: Multi-Head Attention から CVAE の損失関数、推論時の temporal ensembling までを自前で書いています。既存フレームワークのポリシー実装は使いません。
- **アクションヘッドの比較**: 同じバックボーン・同じデータ・同じ評価条件で、`CVAE（ACT 原著）` / `Diffusion (DDPM)` / `Flow Matching` の3種類を比較しました。3種類とも自前で実装するため、条件を揃えた公平な比較ができます（下の「結果: アクションヘッドの比較」）。

### ROS2 を使わなかった理由と今後の課題

講義では ROS2 と Gazebo を扱いましたが、この課題では ROS2 を使っていません。

- **課題の焦点を、アクションヘッドの比較に置いたためです。** シミュレータは ACT 原著と同じ ALOHA（gym-aloha、MuJoCo）にそろえ、公開データセットの人のデモで学習しています。原著・公式実装と同じタスクと設定で、3 種類のヘッドを比べられるようにしました。課題文も、使用ツールは ROS・Gazebo・Genesis などを「想定しているが、他のツールの使用…も可」としています。
- **締切までの時間を、比較の確度を上げることに使いました。** 50 本の評価では手法どうしの差が学習シードによる揺れに埋もれたため、学習シードを 3 本に増やし、学習に使っていない配置（150 本）でも評価しました。ROS2 のノード化よりも、結論の信頼性に効くと判断しました。

ROS2 に載せるための材料は揃っています。

- 推論時間は、ACT が 1 回 6.5 ms、Flow Matching（Euler 1）が 6.5 ms で、50 Hz 制御の 1 ステップ（20 ms）に収まります。Diffusion（DDPM 100）は 125 ms で収まりません。
- どのポリシーも、観測から行動チャンクを出す `predict_chunk` という同じインタフェースを持っています。ノードから呼ぶのはこの関数と、チャンクを実行する [exps/inference.py](src/pai_act/exps/inference.py) の `ChunkExecutor` だけです。

**今後の課題**: 学習済みポリシーを ROS2 Jazzy のノードとして動かすこと。カメラ画像と関節角のトピックを購読し、50 Hz で目標関節角のトピックを出し、temporal ensembling はノードの中で行う、という形を考えています。その先に、実機の ALOHA への移植（sim-to-real）があります。

## スクラッチ実装と借用部分の線引き

原則として、**学習・推論の中身に関わる部分はすべて自前で実装**します。借用するのは物理シミュレータ、ファイル I/O、事前学習済みの画像バックボーンだけです。学習ループの定型処理には PyTorch Lightning を使いますが、ポリシー（モデル）は Lightning に依存しない素の PyTorch の `nn.Module` で、Lightning は `exps/train.py` の中だけで使います。

| 自前で実装する | 借用する |
|---|---|
| Transformer（Multi-Head Attention を含む。`nn.Transformer` / `nn.MultiheadAttention` は使わない） | 物理シミュレータ（gym-aloha / MuJoCo） |
| 位置エンコーディング（画像用の2D版・系列用の1D版） | データセットのダウンロードと読み出し（parquet / 動画デコード） |
| ACT 本体（CVAE エンコーダ + encoder-decoder + 行動チャンクの出力ヘッド） | ResNet18 の ImageNet 事前学習重み |
| CVAE の学習目的関数（再構成損失 + KL項、reparameterization trick） | PyTorch の基本演算・autograd |
| action chunking / temporal ensembling | 学習ループの定型処理（PyTorch Lightning: 逆伝播・更新の呼び出し、混合精度、ログ、保存） |
| 観測・行動の正規化、学習ステップの中身（損失・optimizer の設定）、評価ハーネス | |
| 比較用の Diffusion / Flow Matching ヘッド | |

## 実験のまとめ

transfer cube（ALOHA シミュレータ）で、ACT をスクラッチ実装し、行動を出すヘッドを Diffusion・Flow Matching に替えて比べました。
特に断らない限り、成功率は評価シード 0〜49 の 50 本（キューブの配置は学習デモと同じ。以下「学習内」）、エピソード長 400 ステップ、temporal ensembling ありの値です。
「学習外」は、学習に使っていない配置（評価シード 50〜199）の 150 本です。p 値は、同じ評価シードのエピソードどうしの成否を対応させた McNemar 検定のものです。
詳しい結果は下の各節と、[ACT_IMPLEMENTATION.md](ACT_IMPLEMENTATION.md)・[DIFFUSION_IMPLEMENTATION.md](DIFFUSION_IMPLEMENTATION.md)・[FLOW_MATCHING_IMPLEMENTATION.md](FLOW_MATCHING_IMPLEMENTATION.md) にあります。

### 主な数値

| ヘッド（推論の設定） | 学習内（学習シード 0 / 1 / 2 → 平均） | 学習外（同） | ensembling なしの平均（学習内 / 学習外） | `predict_chunk` の中央値 |
|---|---|---|---|---|
| 仮モデル（baseline、学習シード 0 のみ） | 60% | — | — | — |
| ACT（Decoder 1 層、z = 0） | 72 / 78 / 82% → 77% | 80.7 / 83.3 / 79.3% → 81.1% | 85% / 82.7% | 6.5 ms |
| Diffusion（DDPM 100） | 72 / 80 / 74% → 75% | 57.3 / 78.7 / 72.7% → 69.6% | 61% / 55.1% | 125 ms |
| Flow Matching（Euler 10） | 76 / 82 / 82% → 80% | 78.7 / 72.7 / 83.3% → 78.2% | 74% / 75.6% | 14 ms |
| Flow Matching（Euler 1） | 78 / 80 / 68% → 75% | 76.7 / 63.3 / 56.0% → 65.3% | — | 6.6 ms |

### わかったこと

1. **データとシミュレータの対応は正しいことを、先に確かめました。** デモの行動をそのまま再生すると、50 本すべて成功しました。ただし gym-aloha の既定のエピソード長 300 では、正しいデモでも約 4 割が失敗と判定されます。そのため評価は 400 ステップにしています（「検証結果: デモの再生」）。
2. **スクラッチ実装の ACT は、学習シード 3 本の平均で、学習内 77%、学習外 81% でした。** 仮モデル（60%）より高いものの、学習シード 0 どうしの差（72% と 60%）は偶然の範囲です（成否が分かれた 18 本のうち ACT だけ成功 12 本・仮モデルだけ成功 6 本、McNemar p = 0.24）。計画の目標（80% 台）には、学習内の平均では届きませんでした（「結果: ACT」）。
3. **3 つのヘッドの成功率に、学習シードの揺れを超える差は見られませんでした。** 学習内の平均は 75〜80% で、同じ学習シードの ACT との差はどれも偶然の範囲です（p = 0.39〜1.0）。学習外では Diffusion の平均が低い（69.6%）ものの、主に学習シード 0（57.3%）のためで、学習シード 1 では Flow Matching より高くなっています。同じヘッドでも、学習シードを変えるだけで最大 21 pt 動きました（「結果: アクションヘッドの比較」）。
4. **はっきり差が出たのは推論の速さです。** ACT（6.5 ms）と Flow Matching の Euler 10（14 ms）は、50 Hz 制御の 1 ステップ（20 ms）に収まります。Diffusion の DDPM 100（125 ms）は収まりません。
5. **生成モデルのヘッドは、推論の設定で成功率が大きく変わりました。**
   - Diffusion を決定的な DDIM で速くすると、2〜48% に落ちました。DDIM に毎ステップ乱数を足すと（η = 1）、DDIM 100 は 44% → 72% と DDPM 100 に並びます。DDIM と DDPM の差は、乱数を足すかどうかで説明できます。
   - Flow Matching は、決定的な ODE でも DDIM のようには落ち込まず、学習内ではステップ数 1〜20 で 76〜86% でした。ただし Euler 1 は、学習外では 3 本中 2 本で Euler 10 より低く（−9.3 pt で p = 0.007、−27.3 pt で p < 0.001）、学習シード 2 では学習内でも 82% → 68% に下がりました（p = 0.04）。ACT と同じ速さは、汎化と引き換えになります。
   - temporal ensembling を外すと、Diffusion は学習内でも学習外でも下がりました（学習外では 3 本とも）。ACT は学習内で 8 本のモデルのどれも下がらず、Flow Matching は学習シードで向きがそろいませんでした。
6. **原著・公式実装との食い違いを確かめた ACT の 2 つの変更は、どちらも成功率を上げませんでした。**
   - Decoder 7 層（原著の意図。公式実装はバグで実質 1 層）は、学習内では 1 層と同じでした（2 本の平均で 7 層 76%、1 層 75%）。学習外では 2 本とも 1 層より低く（平均で 7 層 74.3%、1 層 82.0%。学習シード 1 は p = 0.005）、推論も約 1.4 倍遅くなります。
   - 行動クエリの位置ベクトルを固定（論文の記述）にすると、学習内では平均 86%（既定 77%）でした。学習外では 77.3%（既定 81.1%）で、向きが逆になりました。
7. **検証損失は、成功率の目安にも、チェックポイントを選ぶ目安にもなりませんでした。** Diffusion では、検証 MSE が最小になる 18k 付近（20k）の成功率が、学習シード 3 本とも 0% でした。その後、検証 MSE が上がっていく間に、学習内でも学習外でも成功率が上がりました（学習外で 0 → 42.7 → 57.3%）。Diffusion の Decoder を 4 層にすると検証 MSE は下がりましたが、成功率は変わりませんでした。
8. **「学習を早く止めればよい」とは言えませんでした。** 学習シード 0 では、ACT と Flow Matching はどちらも 20k で最も高くなり、ACT は学習外でも 80k を 10 pt 上回りました（p = 0.01）。しかし学習シード 1 では、最も高くなったのは ACT が 60k、Flow Matching が 40k でした。80k は、どのヘッド・学習シードでも 72〜82% で、最も高くはないものの大きく外れてもいません。
9. **学習内と学習外の配置で、成功率の差は小さめでした。** 12 本のモデルの合計で 79.7% と 76.6% です（Fisher p = 0.13）。ただし、条件どうしの比較の向きは変わることがあります（行動クエリの固定、Decoder 7 層、Euler 1）。汎化を論じるには、学習外の配置での評価が要ります。
10. **評価の揺れより、学習シードの揺れのほうが大きく出ました。** 同じチェックポイントを評価し直しても、成功率の幅は 4 pt（50 本中 2 本）でした。学習シードを変えると、6〜21 pt 動きます。失敗する配置は手法によらず偏っていて、学習内の seed 39 は ACT の 8 本のモデルすべて（ensembling あり）で、学習外の seed 119・130 は 24 回の評価のうち 19 回で失敗しました。

### この実験で言えないこと

- **ヘッドの優劣**: 学習シード 3 本・評価 50〜150 本では、ヘッドどうしの成功率の差は学習シードの揺れに埋もれています。
- **ほかのタスク・データ量での傾向**: transfer cube の 1 タスク、人間のデモ 50 本（学習に 45 本）だけの結果です。insertion などほかのタスクや、デモの本数を変えたときに同じ傾向が出るかは確かめていません。
- **失敗の原因**: 失敗の型（届かない・持ち上げない・受け渡さない）は数えましたが、動画で原因を確かめたのは一部だけです。【未確認・推測】の印を付けた説明は、実験で確かめていません。

## 検証結果: デモの再生

モデルを学習する前に、**データセットの行動をシミュレータでそのまま再生すれば成功するか**を確かめました。ここで成功しなければ、学習したモデルがいくら正しくても成功率は上がらないためです。

### 課題: キューブの初期位置がデータに記録されていない

gym-aloha はリセットのたびにキューブの位置を乱数で決めます。一方、データセットにはキューブの位置が保存されていません。そこで次の手順で位置を推定しました。

1. シミュレータでキューブを 7×7 の格子点に置いて描画し、赤いキューブの画素重心を求める
2. 画素重心からテーブル上の (x, y) への写像を2次多項式で当てはめる（当てはめ誤差は最大 0.92 mm）
3. 各デモの初期フレームでキューブの画素重心を求め、2 の写像で位置を推定してシミュレータに配置する

### 結果

| 指標 | 結果 |
|---|---|
| 成功率 | **50 / 50（100%）** |
| 腕関節の追従誤差（データの状態との平均絶対誤差、エピソードごと） | 0.0001〜0.0031 rad |
| 推定したキューブ位置の画素ずれ | 0.5 px 以下 |
| 成功に到達したステップ | 最小 217 / 中央値 290 / 最大 396 |

これで、データの行動空間とシミュレータの行動空間が一致していること、および成功判定が正しく機能していることを確認できました。

### 評価条件についての注意

gym-aloha の既定のエピソード長は **300ステップ（6秒）** です。しかし人間のデモでは **50本中19本が300ステップ以降に成功** しています。既定の長さのままでは、正しいデモでも約4割が「失敗」と判定されてしまいます。

このリポジトリでは、評価のエピソード長をデモと同じ **400ステップ（8秒）** にしています。ACT の公式実装も、transfer cube のエピソード長を 400 にしています（`constants.py` の `episode_len`）。

また、**評価に使うシード 0〜49 のキューブの初期位置は、デモ 50 本の初期位置と 1 対 1 で一致します**（最も近いデモとの距離は 0.2〜3.0 mm）。
学習に使っていない配置は、検証に回した 5 本だけです。そのため、下の成功率は新しい配置への汎化ではなく、主に「学習で見た配置を閉ループで再現できるか」を測っています。
手法どうしの比較は同じ配置で行っているので公平です。確かめ方と、学習外の配置での成功率の集計は [docs/EVALUATION.md](docs/EVALUATION.md) の「評価シード 0〜49 の配置は、学習デモの配置と同じ」にまとめています。

## パイプライン: 学習 → ロールアウト → 動画保存

ACT 本体を実装する前に、**仮モデル**（ResNet18 + MLP で行動チャンクを直接回帰する [baseline](src/pai_act/policies/baseline.py)）を使って、学習から評価までを一通り繋げました。ポリシーは共通インタフェース（[policies/base.py](src/pai_act/policies/base.py)）を実装していれば何でも差し替えられます。ACT などの手法は、ポリシーのファイルを追加するだけで同じ学習・評価コードに載ります。

```
【学習】 scripts/train.sh → exps/train.py
  AlohaDataset（50本のデモ）
    └─ エピソード単位で 学習45本 / 検証5本 に分割
  ChunkDataset: 時刻 t の (画像, 関節角) と、t から k=100 ステップ分の行動チャンクを1サンプルにする
    └─ DataLoader（バッチ8）→ policy.compute_loss → AdamW で更新（PyTorch Lightning の Trainer で回す）
  出力: runs/<name>/ckpt_*.pt（設定・重み・正規化の統計量をまとめて保存）
        runs/<name>/lightning/last.ckpt（学習再開用。optimizer の状態も含む）

【評価】 scripts/evaluate.sh → exps/evaluate.py
  チェックポイントからポリシーを復元
  シード 0..49 でシミュレータをリセット（キューブの位置がシードで決まる）し、閉ループで実行:
    観測 → policy.predict_chunk → ChunkExecutor（action chunking / temporal ensembling）→ env.step → 観測 …
  出力: results.json（成功率・到達段階・失敗の型）と videos/*.mp4（左上にシード・ステップ・報酬を表示）
```

results.json の各項目と、報酬・失敗の型の定義は [docs/EVALUATION.md](docs/EVALUATION.md) にまとめています。

学習と推論で前処理がずれないよう、正規化はポリシーの内部で行い、統計量もポリシーの重みと一緒に保存しています。ポリシーが外とやり取りする値は、どれもシミュレータと同じ単位です。

### 仮モデルでの結果

既定の設定（chunk k=100、バッチ8、20,000ステップ、temporal ensembling あり）で学習・評価しました。学習は RTX 4090 Laptop で約10分、50エピソードの評価は約5分です。

| 指標 | 結果 |
|---|---|
| 成功率（50エピソード） | **30 / 50（60%）** |
| 各段階まで到達した割合 | キューブに触れた 92% / 持ち上げた 80% / 受け渡しを試みた 60% / 成功 60% |
| 失敗20本の内訳（最大報酬） | 触れない 4本 / 触れたが持ち上げられない 6本 / 持ち上げたが受け渡せない 10本 |
| 損失（L1、正規化後） | 学習 0.67 → 0.13 / 検証 0.47（1kステップ）→ 0.25（20kステップ）。検証損失は 8k ステップ以降ほぼ横ばい |

これで、データの読み出しから成功率・動画の出力までが繋がっていることを確認できました。この数値は学習1回・評価シード 0〜49 での結果で、ばらつきはまだ測っていません。ACT との比較で同じ評価条件を使えるよう、仮モデルもベースラインとして残しておきます。

失敗のうち最も多いのは、持ち上げた後の受け渡しです。仮モデルは画像特徴を空間方向に平均しているため、キューブとグリッパーの位置関係のような細かい空間情報が失われることが一因と考えています。ACT では、画像特徴を位置情報付きのトークン列として Transformer で扱います。

## 結果: ACT

スクラッチ実装した ACT（[policies/act.py](src/pai_act/policies/act.py)）を学習し、仮モデルと同じ条件で評価しました。評価条件はシード 0〜49 の 50 エピソード、エピソード長 400 ステップ、temporal ensembling ありです。

### 学習の設定

主な値は ACT 原著・公式実装に合わせました。学習の長さ（80k ステップ）と勾配クリップ（10）は、同じデータセットで学習した LeRobot の公開モデルに合わせています（下の「公式実装・LeRobot の公開モデルとの違い」）。設定は [scripts/train_act.sh](scripts/train_act.sh) にあります。

| 項目 | 値 |
|---|---|
| 行動チャンク k | 100 |
| Transformer | d_model 512 / head 8 / FF 3200 / dropout 0.1 |
| 層数 | Encoder 4 / Decoder 1 / CVAE エンコーダ 4 |
| CVAE | 潜在変数 32 次元、KL の重み β = 10、推論時は z = 0 |
| 行動クエリの位置ベクトル | 学習（公式実装と同じ） |
| 最適化 | AdamW、学習率 1e-5（バックボーンも 1e-5）、weight decay 1e-4、勾配クリップ 10 |
| 学習 | バッチ 8、80,000 ステップ、混合精度（AMP） |
| パラメータ数 | 51.6M |
| 学習時間 | 1 時間 26 分（RTX 4090 Laptop、15.5 it/s） |

Decoder を 1 層にしたのは、原著の設定（7 層）に対して、公式実装ではバグのため 1 層目の出力しか使われていないからです（[tonyzhaozh/act#25](https://github.com/tonyzhaozh/act/issues/25)）。原著の報告値は実質 1 層で出たものと考え、LeRobot と同じく 1 層を既定値にしています。7 層すべてを使った場合との比較は、下の「追加実験」に記しました。

### 公式実装・LeRobot の公開モデルとの違い

比べる相手は 2 つあります。**ACT 公式実装**（[tonyzhaozh/act](https://github.com/tonyzhaozh/act)、論文の著者のコード）と、**LeRobot の公開モデル**（[lerobot/act_aloha_sim_transfer_cube_human](https://huggingface.co/lerobot/act_aloha_sim_transfer_cube_human)）です。LeRobot は ACT を独自に実装し直したライブラリで、公開モデルはそれを同じデータセットで学習したものです。公式実装とはコードが別です。

モデルの構成と最適化の設定（AdamW、学習率 1e-5、バッチ 8、chunk 100、KL の重み 10、上方カメラ 1 台）は公式実装と同じです。違うのは次の点です（2026/10/25 に、公式実装のコードと、公開モデルの `config.json`・`train_config.json`・モデルカードで確認）。

| 項目 | ACT 公式実装 | LeRobot の公開モデル | このリポジトリ |
|---|---|---|---|
| 学習 / 検証の分け方 | 40 本 / 10 本（`train_ratio = 0.8`） | 50 本 / なし（`dataset.episodes = None`） | 45 本 / 5 本 |
| 正規化の統計量 | 50 本すべて（検証用を含む）から計算し、`dataset_stats.pkl` に別に保存 | 調べていない | 学習用の 45 本だけから計算し、チェックポイントに同梱 |
| 学習の長さ | 2,000 エポック（README の例。スクリプトで生成したデモで学習する場合）。1 エポックは各エピソードから 1 時刻ずつ取った 40 サンプルなので、更新は計 1 万回 | 80,000 回（100,000 回まで学習した途中のチェックポイント） | 80,000 回（公開モデルに合わせた） |
| 勾配クリップ | なし | ノルム 10（`optimizer.grad_clip_norm`） | ノルム 10（公開モデルに合わせた） |
| 計算精度 | 32 ビット（混合精度の設定がない） | 32 ビット（`use_amp = false`） | bf16 の混合精度 |
| 評価するチェックポイント | 検証損失が最小のもの（`policy_best.ckpt`） | 80k ステップのもの | 最後のもの（80k） |
| temporal ensembling | `--temporal_agg` を付けると有効（m = 0.01） | なし（`temporal_ensemble_coeff = None`。100 ステップごとに推論し直す） | あり（m = 0.01） |
| 評価のエピソード長 | 400 | 調べていない | 400 |

- 公式実装は、検証損失が最小のチェックポイントを評価します。このリポジトリでは検証損失が成功率の目安にならず、Diffusion では検証損失が最小に近い 20k ステップのチェックポイントの成功率が 0% でした（下の「学習の進みと成功率」）。
- 公開モデルのモデルカードには、成功率 83.0%（500 エピソード）とあります。同じ表で、公式実装で学習したモデルを LeRobot で評価した値は 68.0% です。83.0% は 2025-02-03 の更新で書き換わった値で、それ以前は 87.6% でした。評価の条件（配置、本数）がこのリポジトリと違うので、成功率は直接は比べません。

### 結果（仮モデルとの比較）

| 指標 | 仮モデル（baseline） | ACT |

### 評価の再現性

同じチェックポイントを同じシード 0〜49 で 2 回評価したところ、結果が完全には一致しませんでした。

- 50 本中 24 本で、終了までのステップ数か最大報酬が変わりました。ほとんどは成功までのステップが 1〜6 ずれただけです。
- 成否が入れ替わったエピソードが 2 本ありました（seed 7: 失敗 → 成功、seed 13: 成功 → 失敗）。成功率はたまたま同じ 72% でした。
- 最大報酬が 1 → 2 に変わったエピソードが 3 本あり（seed 2, 5, 22）、失敗の内訳は大きく変わりました（`not_lifted` 6 → 3 本、`not_transferred` 6 → 9 本）。

シミュレータの初期配置はシードで決まるので、違いはポリシーの推論から来ていると考えています。GPU の計算は、cuDNN が選ぶアルゴリズム（`cudnn.benchmark`）などによって、浮動小数点の丸め誤差の出方が実行ごとに変わることがあります。閉ループでは、そのわずかな行動の差が次の観測を変え、接触の有無のような離散的な結果まで変えてしまいます。そのため、1 回の評価での失敗の内訳や、シードごとの成否には、学習のばらつきとは別に評価自体のばらつきが含まれます。

10/24 に、3 つのヘッド（下の「結果: アクションヘッドの比較」）の学習シード 0 のチェックポイントを、同じ条件（シード 0〜49）で評価し直しました。ACT と Flow Matching は 3 回、Diffusion は 2 回です。元の評価と合わせると、それぞれ 4 回・4 回・3 回になります。

| ヘッド（推論の設定） | 成功率（評価ごと） | 1 回でも成否が変わった seed | 終了までのステップ数か最大報酬が変わったエピソード |
|---|---|---|---|
| ACT | 72 / 74 / 70 / 74% | 3 本（seed 7, 13, 46） | 50 本中 37 本 |
| Flow Matching（Euler 10） | 76 / 76 / 76 / 80% | 2 本（seed 37, 41） | 50 本中 43 本 |
| Diffusion（DDPM 100） | 72 / 70 / 74% | 4 本（seed 0, 3, 25, 46） | 50 本中 40 本 |

- 成功率の幅は、3 つのヘッドとも 4 pt（50 本中 2 本）でした。2 回の評価をどう組にしても、McNemar p は 0.5 以上です。
- Diffusion と Flow Matching は、評価のたびに推論の乱数（初期ノイズ）が変わります。それでも成否の揺れは、乱数を使わない ACT と同じくらいでした。
- 細かい動きは毎回変わります。終了までのステップ数か最大報酬が変わったエピソードは、50 本中 37〜43 本ありました。
- 学習シードを変えたときの差（学習内の配置で 6〜10 pt、学習外の配置では最大 21 pt）に比べると、評価の揺れは小さいです。ただし評価し直したのは 3〜4 回だけなので、揺れの幅を少なめに見積もっている可能性はあります。

### まとめ

- **自前の ACT で成功率 72% が出ました。** すべての段階の到達率で仮モデルを上回っています。差が大きいのは持ち上げるまでの段階で、持ち上げた割合は 80% から 90% に上がりました。
- **ただし、仮モデルとの差（12 ポイント）は偶然の範囲に収まる大きさです。** 同じシードのエピソードを組にすると、成否が分かれた 18 本のうち ACT だけ成功 12 本・仮モデルだけ成功 6 本で、McNemar の正確検定で p = 0.24 です。95% 信頼区間（Wilson）は ACT が 58〜83%、仮モデルが 46〜72% で重なっています。どちらも学習 1 回・評価 50 回の結果です。さらに、同じチェックポイントを評価し直すだけでも、成否が変わるエピソードがありました（「評価の再現性」を参照）。学習シードを変えた追加の学習で、ばらつきを確かめる必要があります。
- **最も多い失敗は、持ち上げた後に受け渡しへ入れないことです。** 失敗 14 本のうち 9 本が `not_transferred` で、仮モデル（20 本中 10 本）と同じ傾向です。一方で、「受け渡しを試みた」と「成功」の割合はどちらも 72% で、左グリッパーがキューブに触れたエピソードはすべて成功しました。ACT は掴んで持ち上げるところまでは改善しましたが、持ち上げたキューブを受け渡し位置まで運ぶ段階が残った課題です。
- **CVAE の潜在変数 z は、ほとんど情報を持っていない可能性があります。** KL がほぼ 0 ということは、エンコーダの出力 N(μ, σ²) が事前分布 N(0, I) とほぼ一致していることを意味します。β = 10 では KL の項が強く効き、Decoder は z をほとんど使わずに観測だけから行動を出している（決定的な回帰に近い）と考えられます。z を事前分布からサンプルして出力がどれだけ変わるかを調べれば確かめられます。
- **検証 L1 は成功率の目安になりませんでした。** 検証 L1 は仮モデルと ACT でほぼ同じ（0.25）なのに、成功率は 12 ポイント違います。L1 は行動を 1 ステップずつ比べるだけで、閉ループで誤差が積み重なったときの振る舞いや、掴めたかどうかを反映しないためと考えています。
- **推論は制御周期に十分収まります。** `predict_chunk` 1 回は平均 6〜7 ms（1 回目 6.1 ms / 2 回目 7.1 ms）で、50 Hz 制御の 1 ステップ（20 ms）より短いです。
- 計画の目標（80% 台）にはまだ届いていません。次は、Decoder 層数（1 層 / 7 層）と行動クエリの位置ベクトル（学習 / 固定）の比較実験、および学習シードを変えた再学習を行います。

### 追加実験

上の既定の設定（Decoder 1 層・学習する行動クエリ・temporal ensembling の係数 m = 0.01）から 1 か所だけ変えて比べました。評価条件は上と同じです（シード 0〜49 の 50 エピソード、400 ステップ）。p 値は、同じシードのエピソードどうしの成否を対応させた McNemar 検定のものです。比較表と図は [outputs/compare/](outputs/compare/) にあり、詳しい結果は [ACT_IMPLEMENTATION.md](ACT_IMPLEMENTATION.md) のステップ 8〜11 に記録しています。

**学習シードを変えた再学習と、モデルの 2 つの変更**（既定と行動クエリ固定は学習シード 0 / 1 / 2 の 3 本ずつ、Decoder 7 層はシード 0 / 1 の 2 本。学習シードを変えると、学習・検証のエピソード分割、重みの初期値、ミニバッチの順番が変わります）

| 条件 | シード 0 | シード 1 | シード 2 | 平均 | 同じシードの既定との差（McNemar p） |
|---|---|---|---|---|---|
| 既定（Decoder 1 層・学習する行動クエリ） | 72% | 78% | 82% | 77% | — |
| Decoder 7 層（原著の設定。全層の出力を使う） | 76% | 76% | — | 76% | +4 pt（0.75） / −2 pt（1.0） / — |
| 行動クエリの位置ベクトルを固定 sinusoidal（論文の記述） | 88% | 82% | 88% | 86% | +16 pt（0.01） / +4 pt（0.69） / +6 pt（0.45） |

- 学習シードを変えるだけで、既定の設定の成功率は 72% → 78% → 82% と動きました（シード 0 と 2 の差は +10 pt、McNemar p = 0.23）。
- Decoder を 7 層にしても、成功率は変わりませんでした（シード 0 / 1 の平均で 75% と 76%）。7 層ではパラメータ数が 51.6M → 83.9M に増え、学習時間は約 1.5 倍（2 時間 6〜9 分）、推論時間（`predict_chunk` の中央値）は 6.5 → 9.2 ms になります。学習外の配置（シード 50〜199 の 150 本）では、2 本とも 7 層のほうが低くなりました（80.7% → 76.0%、83.3% → 72.7%。学習シード 1 は McNemar p = 0.005）。7 層で増えた失敗は、キューブに触れずに終わる `no_touch` です（1 → 13 本、4 → 15 本。[ACT_IMPLEMENTATION.md](ACT_IMPLEMENTATION.md) のステップ 9）。
- 行動クエリを固定にすると、3 本とも既定より高く、平均で 9 ポイント上回りました。ただし、はっきりした差が出たのはシード 0 だけです（p = 0.01）。シード 1・2 では差は偶然の範囲でした（p = 0.69、0.45）。シード 0 では「持ち上げた後に受け渡しへ入れない」失敗（`not_transferred`）が 9 本 → 1 本に減りましたが、シード 1・2 ではこの傾向は再現しませんでした（4 本 → 6 本、3 本 → 3 本）。
- ただし、学習外の配置（シード 50〜199）で評価すると、3 本の平均では既定のほうが高く、行動クエリの比較の向きは逆になりました（下の「学習外の配置（シード 50〜199）での評価」）。上の表の差は、学習で見た配置の再現の差かもしれません。
- 検証 L1 は、どの条件もほぼ同じ（0.252〜0.277）でした。成功率の違いは検証 L1 に表れていません。
- seed 39 のエピソードは、8 本のモデルすべてで失敗しました（学習シード 2 では学習外の配置）。seed 29 も 8 本中 7 本で失敗しました。どのモデルでも失敗しやすいキューブの配置があります。

**temporal ensembling の係数と有無**（学習シード 0 の既定のモデル 1 本を、評価の設定だけ変えて評価）

推論は毎ステップ行います。時刻 t の行動は、t をカバーする過去の予測を重み exp(−m·i) で平均したものです。i = 0 が最も古い予測なので、m が大きいほど古い予測の重みが大きくなります。ensembling なしでは、100 または 50 ステップごとに推論し直し、その間は予測したチャンクをそのまま実行します。

| 条件 | 成功率 | 既定との差（McNemar p） | 失敗の内訳（`no_touch` / `not_lifted` / `not_transferred`） |
|---|---|---|---|
| m = 0（単純平均） | 74% | +2 pt（1.0） | 2 / 7 / 4 |
| m = 0.01（既定・原著の値） | 72% | — | 2 / 3 / 9 |
| m = 0.1 | 70% | −2 pt（1.0） | 1 / 5 / 9 |
| m = 1 | 62% | −10 pt（0.18） | 1 / 5 / 13 |
| ensembling なし（100 ステップごと） | 84% | +12 pt（0.11） | 0 / 0 / 8 |
| ensembling なし（50 ステップごと） | 82% | +10 pt（0.06） | 0 / 4 / 5 |

- m を大きくして古い予測に寄せるほど、成功率は下がる方向に動きました（74 → 72 → 70 → 62%）。ただし、既定との差はどれも偶然の範囲です。m = 1 で増えた失敗は、主に `not_transferred` でした。
- ensembling をなくすと、成功率は 84% と 82% で、既定より高い方向に出ました。50 本では差があるとは言い切れません（p = 0.11 と 0.06）。ただし、成否が分かれたエピソードは、なしの側に偏っていました（既定だけ成功 2 本・なしだけ成功 8 本、50 ステップごとでは 0 本と 5 本）。
- 同じ比較を Diffusion ヘッド（DDPM 100 ステップ）で行うと、ensembling をなくしたときに 72% → 48% と下がりました（p = 0.01、[DIFFUSION_IMPLEMENTATION.md](DIFFUSION_IMPLEMENTATION.md) の D10）。ACT では下がらず、ensembling の効き方は 2 つのヘッドで違いました。
- m の比較は、学習シード 0 の既定のモデル 1 本での結果です。

**ensembling の有無を 8 本のモデルで確かめる**（上の 8 本のモデルを、ensembling なし・100 ステップごとでも評価。p は同じモデルのあり / なしの McNemar 検定）

| モデル | あり（m = 0.01） | なし（100 ステップごと） | 差（McNemar p） |
|---|---|---|---|
| 既定、シード 0 | 72% | 84% | +12 pt（0.11） |
| 既定、シード 1 | 78% | 88% | +10 pt（0.12） |
| 既定、シード 2 | 82% | 82% | ±0 pt（1.0） |
| Decoder 7 層、シード 0 | 76% | 82% | +6 pt（0.45） |
| Decoder 7 層、シード 1 | 76% | 82% | +6 pt（0.45） |
| 行動クエリ固定、シード 0 | 88% | **90%** | +2 pt（1.0） |
| 行動クエリ固定、シード 1 | 82% | 84% | +2 pt（1.0） |
| 行動クエリ固定、シード 2 | 88% | **90%** | +2 pt（1.0） |

- 8 本中 7 本で ensembling なしのほうが高い方向に出て、残る 1 本（既定、シード 2）は同じでした。下がったモデルはありません。1 本ずつでは、どれも差があるとは言い切れません。上がり幅は、ensembling ありの成功率が低いモデルほど大きく、なしの成功率は 82〜90% に収まりました。
- seed 39 のエピソードは、ensembling ありでは 8 本すべてで失敗し、なしでは 8 本すべてで成功しました。一方 seed 29 は、なしでも 8 本中 7 本で失敗しました。
- ただし、学習外の配置（シード 50〜199 の 150 本）では、ensembling なしで下がるモデルもあり、向きはそろいませんでした（既定の 3 本で −8.7 / +4.0 / +9.3 pt。下の「学習外の配置（シード 50〜199）での評価」）。
- ensembling なしでは推論の回数が約 1/100 になりますが、`predict_chunk` 1 回の時間の中央値は約 33 ms（7 層では約 44 ms）に増えました。理由は調べていません。

## 結果: アクションヘッドの比較

ACT と同じ観測トークン列（[policies/trunk.py](src/pai_act/policies/trunk.py)）・データ・学習の設定（80k ステップ、学習率 1e-5、バッチ 8）で、行動を出すヘッドだけを Diffusion（[policies/diffusion.py](src/pai_act/policies/diffusion.py)）と Flow Matching（[policies/flow_matching.py](src/pai_act/policies/flow_matching.py)）に替えて比べました。Diffusion と Flow Matching は同じデノイザ（[policies/denoiser.py](src/pai_act/policies/denoiser.py)、34.7M パラメータ）を使います。評価条件は ACT と同じです（シード 0〜49 の 50 エピソード、400 ステップ、temporal ensembling あり）。詳しい結果は [DIFFUSION_IMPLEMENTATION.md](DIFFUSION_IMPLEMENTATION.md) の D8〜D11 と [FLOW_MATCHING_IMPLEMENTATION.md](FLOW_MATCHING_IMPLEMENTATION.md) の F6・F7 に記録しています。

| ヘッド（推論の設定） | デノイザを呼ぶ回数 | シード 0 | シード 1 | シード 2 | 平均 | ensembling なし（シード 0 / 1 / 2 → 平均） | `predict_chunk` の中央値 |
|---|---|---|---|---|---|---|---|
| ACT（CVAE、z = 0） | 1 | 72% | 78% | 82% | 77% | 84 / 88 / 82% → 85% | 6.5 ms |
| Diffusion（DDPM 100） | 100 | 72% | 80% | 74% | 75% | 46 / 64 / 74% → 61% | 125 ms |
| Diffusion（DDIM 10、x̂_0 のクリップ 2） | 10 | 44% | 48% | — | 46% | — | 16 ms |
| Flow Matching（Euler 10） | 10 | 76% | 82% | 82% | 80% | 76 / 72 / 74% → 74% | 14 ms |

「ensembling なし」は、100 ステップごとに推論し、その間は予測したチャンクをそのまま実行します。

- 3 つのヘッドの成功率は、Diffusion を DDPM 100 ステップで推論すれば同じくらいでした（3 本の平均で 75〜80%）。同じ学習シードの ACT と比べた差は、どれも偶然の範囲です（McNemar p = 0.39〜1.0）。同じヘッドでも学習シードで 6〜10 ポイント動くので、この程度の差は手法の違いとは言えません。
- temporal ensembling を外すと、ヘッドによって効き方が分かれました。ACT は 3 本とも下がりませんでした（+12 / +10 / ±0 pt）。Diffusion は 3 本中 2 本で下がり（−26 pt で McNemar p < 0.01 / −16 pt で p = 0.10 / ±0 pt）、Flow Matching も ±0 / −10 / −8 pt と下がる方向でした（p = 0.30〜1.0）。外したときに増えた失敗は、Diffusion と Flow Matching では `not_transferred`（持ち上げたが受け渡しに進まない）です（Diffusion 2〜6 本 → 9〜19 本、Flow Matching 4 本 → 8〜12 本）。ACT では増えませんでした（9 / 4 / 3 本 → 8 / 2 / 4 本）。【未確認・推測】推論のたびに別のサンプルを出す生成モデルでは、チャンクの切り替わりで行動が飛び、ensembling の平均がそれをならしていると考えています（動画では確かめていません）。
- 推論時間には大きな差があります。DDPM 100 は 1 回 125 ms で、50 Hz 制御の 1 ステップ（20 ms）に収まりません。Flow Matching は Euler 10 で 14 ms に収まり、ステップ数を 1〜20 と変えても成功率は 76〜86% でした（F7）。
- Diffusion を DDIM（決定的なサンプラー）で速くすると、成功率が下がりました。DDIM 10 は既定のクリップ 6 で 2%、クリップ 2 で 44% で、ステップ数を 100 に増やしても 44% でした（D8・D9）。
- DDIM に毎ステップ乱数を足すと（η = 1）、DDIM 100 は 44% → 72% と DDPM 100 に並びました（p < 0.01）。DDIM 10 でも 44% → 60%、DDIM 20 では 44% → 66% に上がりました（D11）。DDIM と DDPM の差は、乱数を足すかどうかで説明できます。増えた成功の多くは、キューブに触れない失敗（`no_touch`）が減った分でした。
- 学習シード 1 でも同じ結果になりました。DDIM 100 は η = 1 で 80% と DDPM 100（80%）に並び、成否が分かれたのは 2 本だけでした。DDIM 10（クリップ 2）は η = 0 → 1 で 48% → 66% に上がりました（p = 0.01）。
- Flow Matching の推論も乱数を足さない決定的な ODE ですが、DDIM のような落ち込みはありませんでした。ステップ数を減らしても成功率はほとんど変わらず、学習シード 1 でも Euler 1 / 2 / 5 / 10・Heun 5 が 80〜82% でした。Euler 1 なら `predict_chunk` は 6.5 ms で、ACT と同じ速さです（F7）。ただし学習外の配置（150 本）では、Euler 1 は 3 本中 2 本で Euler 10 より低くなりました（学習シード 1 で 72.7% → 63.3%、p = 0.007。学習シード 2 で 83.3% → 56.0%、p < 0.001）。学習シード 2 では、学習内でも 82% → 68% に下がりました（p = 0.04）。Euler 1 の速さは、新しい配置での成功率と引き換えになります。

### Diffusion の Decoder 層数（1 層 / 4 層）

Diffusion の Decoder を 4 層にして学習し直し、既定の 1 層と比べました（10/19 の夜間実行 [scripts/night_1019.sh](scripts/night_1019.sh)、実行名 `diffusion_dec4`）。
学習シード 0 の 1 層のモデルでは、ノイズの小さい時刻 t で、ε の予測誤差が学習用と検証用のエピソードで大きく違っていました。そこで、Decoder を深くすれば ε の予測が良くなり、成功率も上がるかを確かめました。
層数以外は [scripts/train_diffusion.sh](scripts/train_diffusion.sh) の設定（学習シード 0、80k ステップ）と同じです。評価条件は上と同じです（シード 0〜49 の 50 エピソード、400 ステップ、temporal ensembling あり）。

| 項目 | Decoder 1 層（既定） | Decoder 4 層 |
|---|---|---|
| パラメータ数 | 34.7M | 50.9M |
| 学習時間 | 1 時間 8 分（19.7 it/s） | 1 時間 28 分（15.1 it/s） |
| 検証 MSE（最終 / 最小） | 0.116 / 0.056（18k） | 0.075 / 0.039（33k） |
| 成功率: DDPM 100 | 72%（36/50） | 70%（35/50） |
| 成功率: DDIM 10、x̂_0 のクリップ 2 | 44%（22/50） | 38%（19/50） |
| `predict_chunk` の中央値: DDPM 100 / DDIM 10 | 125 / 16 ms | 339 / 36 ms |
| DDPM 100 の失敗の内訳（`no_touch` / `not_lifted` / `not_transferred` / `transfer_failed`） | 10 / 2 / 2 / 0 | 1 / 7 / 7 / 0 |

- **Decoder を 4 層にしても、成功率は上がりませんでした。** DDPM 100 では、1 層だけ成功したエピソードが 12 本、4 層だけ成功したエピソードが 11 本で、McNemar p = 1.0 です。DDIM 10（クリップ 2）でも 11 本と 8 本で、p = 0.65 です。成功率は同じくらいでも、成功するエピソードはかなり入れ替わっています。
- **検証 MSE は下がったのに、成功率には表れませんでした**（最小 0.056 → 0.039）。検証損失が成功率の目安にならない例の一つです（下の「学習の進みと成功率」）。ACT の Decoder 1 層 / 7 層の比較では、検証 L1 も成功率も変わりませんでした（上の「追加実験」）。
- 失敗の型は変わりました。4 層では `no_touch` が 10 本から 1 本に減り、その代わり `not_lifted` と `not_transferred` が 2 本ずつから 7 本ずつに増えました。ただし、1 層でも学習シード 1 では `no_touch` が 2 本だけでした。【未確認・推測】`no_touch` が減ったのは、層数ではなく学習シードによるばらつきかもしれません。
- 推論は 2〜3 倍遅くなりました。Diffusion はデノイザ（Decoder 側）を推論 1 回で 100 回（DDPM）呼ぶので、Decoder の層数がそのまま推論時間に効きます。成功率が変わらないので、既定は 1 層のままにしています。
- 比べたのは学習シード 0 の 1 本ずつだけです。

|---|---|---|
| ACT 既定 | 81.1% | 82.7% |
| ACT 行動クエリ固定 | 77.3% | 76.2% |
| Flow Matching Euler 10 | 78.2% | 75.6% |
| Diffusion DDPM 100 | 69.6% | 55.1% |

- **学習外の配置で、成功率が大きく下がることはありませんでした。** 12 本を合わせると、ensembling ありで学習内 79.7%、学習外 76.6% です（Fisher p = 0.13）。モデルごとに比べて p < 0.05 になったのは、24 組中 2 組だけでした。どちらも行動クエリ固定・ensembling なしです（シード 0: 90% → 76%、シード 2: 90% → 74%）。ensembling ありで最も下がったのは Diffusion・シード 0 の 72% → 57.3% です（p = 0.07）。
- **ヘッドどうしの差は、学習シードによって変わりました。** ensembling ありの 3 本の平均は、ACT 81.1%、Flow Matching 78.2%、Diffusion 69.6% でした。
  - ACT と Flow Matching の差は、学習シードで向きが変わります。シード 1 では ACT が上（83.3% と 72.7%、McNemar p = 0.03）、シード 2 では Flow Matching が上（79.3% と 83.3%、p = 0.36）、シード 0 では差がありません（p = 0.72）。
  - Diffusion の平均が低いのは、主にシード 0（57.3%）のためです。シード 0 では 150 本中 46 本がキューブに触れずに終わり（`no_touch`）、ACT・Flow Matching との差は p < 0.001 でした。シード 1 では Diffusion が Flow Matching より高く（78.7% と 72.7%、p = 0.25）、シード 2 では Flow Matching より低くなりました（72.7% と 83.3%、p = 0.02）。
  - 同じヘッドでも学習シードで最大 21 pt 動く（Diffusion の 57.3〜78.7%）ので、学習シード 1 本だけでヘッドの優劣は決められません。
- **ensembling を外すと、Diffusion だけは学習外でも 3 本とも下がりました**（−8.0 / −24.0 / −11.3 pt、McNemar p = 0.16 / < 0.001 / 0.03）。増えた失敗は `not_transferred`（持ち上げたが受け渡しに進まない。14 → 33、21 → 43、18 → 35 本）で、学習内の 50 本と同じ傾向です（[DIFFUSION_IMPLEMENTATION.md](DIFFUSION_IMPLEMENTATION.md) の D10）。ほかのモデルは向きがそろいませんでした。ACT 既定は −8.7 / +4.0 / +9.3 pt（シード 2 は p = 0.02 で上がる）、Flow Matching は +4.0 / −0.7 / −11.3 pt（シード 2 は p < 0.01 で下がる）、行動クエリ固定は −1.3 / +4.0 / −6.0 pt です。
- **行動クエリの比較は、学習内と学習外で向きが逆になりました。** 学習内では固定版が 3 本とも既定版以上でした（平均 86% と 77%）。学習外では、3 本の平均で既定版が上です（ensembling あり 81.1% と 77.3%、なし 82.7% と 76.2%）。1 本ずつでは、既定版が上で p < 0.05 になったのは、ありではシード 1（+8.7 pt、p = 0.04）、なしではシード 1（+8.7 pt、p = 0.01）とシード 2（+14.7 pt、p < 0.001）です。シード 2 のありは差がなく（79.3% と 80.0%、p = 1.0）、シード 0 のなしは固定版が上でした（72.0% と 76.0%、p = 0.36）。固定版は ensembling ありで 3 本とも学習内より学習外のほうが低く（88 → 77%、82 → 75%、88 → 80%）、既定版は 3 本中 2 本で学習外のほうが高くなっています。【未確認・推測】固定版は学習した配置の再現は得意でも、配置が変わったときの汎化は既定版より弱い可能性があります。
- 学習外の配置でも、失敗は特定の配置に集中しました。24 回の評価（12 本 × ensembling の有無）で、seed 119 と 130 は 19 回、seed 128 は 17 回失敗しました。一方、150 本中 8 本は 24 回とも成功しました。
- 95% 信頼区間の幅は、50 本のときの約 ±12 pt から、150 本で約 ±7 pt、0〜49 と合わせた 200 本で約 ±6 pt に縮みました。
- 10/25 に、Flow Matching の Euler 1（学習シード 0 / 1 / 2）と ACT の Decoder 7 層（学習シード 0 / 1）も学習外の配置で評価しました。どちらも、学習内の 50 本では基準（Euler 10、Decoder 1 層）との差がほとんどなかったのに、学習外では低くなるモデルがありました（Euler 1 は 78.7 / 72.7 / 83.3% → 76.7 / 63.3 / 56.0%、Decoder 7 層は 80.7 / 83.3% → 76.0 / 72.7%）。上の「追加実験」と「結果: アクションヘッドの比較」に書いています。比較表と図: [outputs/compare/flow_matching_euler1_ood/](outputs/compare/flow_matching_euler1_ood/)、[outputs/compare/act_dec7_ood/](outputs/compare/act_dec7_ood/)

比較表と図: [outputs/compare/ood150/](outputs/compare/ood150/)（学習外の 150 本だけ）、[outputs/compare/eval200/](outputs/compare/eval200/)（200 本の合計。学習内と学習外が混ざった値なので、上の表では分けています）

### 学習の進みと成功率

途中のチェックポイント（10k ステップごとに保存）を評価しました。学習シード 0 の学習内の配置は 10/24、学習外の配置と学習シード 1 / 2 は 10/25 の夜間実行です。Diffusion の DDPM 100 は、50 本に約 40〜50 分、150 本に約 2〜2.5 時間かかるので、20k と 40k だけです。80k は上の表の最後のチェックポイントの評価です。評価の設定は ensembling ありで、上の表と同じです。

学習内の配置（シード 0〜49、50 本）:

| ステップ | 10k | 20k | 30k | 40k | 50k | 60k | 70k | 80k |
|---|---|---|---|---|---|---|---|---|
| ACT、学習シード 0 | 70% | **84%** | 78% | 80% | 78% | 74% | 74% | 72% |
| ACT、学習シード 1 | 40% | 70% | 72% | 76% | 84% | **90%** | 88% | 78% |
| Flow Matching（Euler 10）、学習シード 0 | 70% | **86%** | 76% | 70% | 84% | 82% | 80% | 76% |
| Flow Matching（Euler 10）、学習シード 1 | 24% | 78% | 82% | **84%** | 54% | 74% | 82% | 82% |
| Diffusion（DDPM 100）、学習シード 0 | — | 0% | — | 46% | — | — | — | **72%** |
| Diffusion（DDPM 100）、学習シード 1 | — | 0% | — | 24% | — | — | — | **80%** |
| Diffusion（DDPM 100）、学習シード 2 | — | 0% | — | 22% | — | — | — | **74%** |

学習外の配置（シード 50〜199、150 本、学習シード 0）:

| ステップ | 20k | 40k | 80k |
|---|---|---|---|
| ACT | **90.7%** | 79.3% | 80.7% |
| Flow Matching（Euler 10） | **86.7%** | 71.3% | 78.7% |
| Diffusion（DDPM 100） | 0.0% | 42.7% | **57.3%** |

検証損失が最小になったステップは、学習シード 0 では、ACT が 30k 以降横ばい（検証 L1）、Flow Matching が 16k、Diffusion が 18k です（検証 MSE。Flow Matching と Diffusion は、その後は上がり続けました）。Flow Matching の学習シード 1 は 13k です。

- **Diffusion は立ち上がりが遅く、20k では学習シード 3 本とも 0% でした。** ほぼすべてのエピソードが、キューブに触れずに終わっています（学習内では 50 本中 43〜49 本、学習外では 150 本中 134 本）。40k でも 22〜46% で、3 本とも 80k（72〜80%）より低いままでした（McNemar p ≤ 0.02）。同じデノイザ・同じ学習の設定の Flow Matching は、20k で 78〜86% に届いています。
- **Diffusion の成功率は、検証 MSE が最小になった後も、学習外の配置で上がり続けました**（0 → 42.7 → 57.3%。80k との差は p < 0.001 と p = 0.01）。この間、検証 MSE は 0.056（18k）→ 0.109（40k）→ 0.116（80k）と上がっています。検証 MSE は学習外の 5 本で測るので、「成功率は学習内の配置で測るから、検証 MSE と食い違う」わけではありませんでした。【未確認・推測】検証 MSE は 1 回のデノイズでの ε の予測誤差です。100 回のデノイズを重ねた後のチャンクの質とは、別のものを見ていると考えています（20k は、学習に使ったエピソードでも、オープンループで出したチャンクが正解から大きくずれていました。L1 1.75、80k は 0.40。D8）。検証 MSE が最小のチェックポイントを選んでいたら、成功率 0% のモデルになっていました。
- **ACT と Flow Matching は、学習シード 0 では 20k が最も高くなりました。** 学習外の配置でも同じで、ACT は 80k を 10 pt 上回り、差がはっきりしました（McNemar p = 0.01）。Flow Matching は +8 pt（p = 0.07）です。学習内の 50 本では、どちらも 80k との差は偶然の範囲でした（ACT +12 pt で p = 0.15、Flow Matching +10 pt で p = 0.33）。
- **ただし、最も高くなるステップは学習シードによって変わりました。** 学習シード 1 では、ACT は 60k まで上がり続け（90%）、Flow Matching は 40k（84%）が最も高くなりました。Flow Matching の学習シード 1 では、50k だけ 54% に落ちています（80k との差は p < 0.001。前後は 84% と 74%）。「何 k ステップで止めればよい」という固定の値は決まりませんでした。80k は、どのヘッド・学習シードでも 72〜82% で、最も高くはないものの、大きく外れてもいません。
- 検証損失は、成功率の目安にも、チェックポイントを選ぶ目安にもなりませんでした（ACT の「まとめ」、[DIFFUSION_IMPLEMENTATION.md](DIFFUSION_IMPLEMENTATION.md) の D8、[FLOW_MATCHING_IMPLEMENTATION.md](FLOW_MATCHING_IMPLEMENTATION.md) の F6）。

### 構成の考え方

- **公平な比較を構造で保証する**: 画像・状態を観測トークン列にする部分（`policies/trunk.py`）を3手法で共有し、違いはヘッドだけにしています。全ポリシーが `policies/base.py` の共通インタフェースを実装するので、学習ループ（`exps/train.py`）と評価（`exps/evaluate.py`）は1つずつです。
- **借用部分をファイル単位で閉じ込める**: 借用は `data/dataset.py`、`nn/backbone.py`、`exps/sim.py` の3ファイルに限っています。上の「スクラッチ実装と借用部分の線引き」の表と対応しています。
- **参考にした構成**: 部品の分け方（backbone / transformer / position encoding）は [DETR](https://github.com/facebookresearch/detr) と、それを流用した [ACT 公式実装](https://github.com/tonyzhaozh/act) を参考にしました。手法ごとにポリシーを分けて共通インタフェースを持たせる形は、[LeRobot](https://github.com/huggingface/lerobot) と [Diffusion Policy](https://github.com/real-stanford/diffusion_policy) を参考にしています。参考にしたのは構成だけで、コードは自前で書いています。

## 実行方法

実行は `scripts/` のシェルスクリプトから行います。中では、リポジトリ直下に移動してから `uv run python -m pai_act.exps.<名前>` を呼んでいます。スクリプトの後ろに付けた引数はそのまま Python 側に渡り、スクリプト内の設定より優先されます。

```bash
# デモの再生検証（全50本）。初回のみデータセットのダウンロードと動画のデコード（約18GB のキャッシュ作成）が走る
bash scripts/replay_demo.sh

# 一部のエピソードだけ再生し、比較動画（左: シミュレータ / 右: デモ）を保存する
bash scripts/replay_demo.sh --episodes 0 1 2 --video-episodes 0
```

出力は `outputs/` に保存されます。

### 学習と評価
