# 評価の出力の読み方

`bash scripts/evaluate.sh --ckpt runs/<name>/ckpt_last.pt` が出力する `results.json` と動画について、各項目の意味と、報酬・失敗の型の定義をまとめます。
評価の処理は [src/pai_act/exps/evaluate.py](../src/pai_act/exps/evaluate.py) にあります。

## 報酬（reward）の定義

transfer cube の報酬は gym-aloha（`gym_aloha/tasks/sim.py` の `TransferCubeTask.get_reward`）が定義しています。
報酬は**毎ステップ、その瞬間の接触だけから決まり**、下の条件のうち満たすもので最も大きい値になります。
接触の判定は MuJoCo の接触ペアで行います。

| 報酬 | 条件（その瞬間の接触） | 意味 |
|---|---|---|
| 0 | 右グリッパーの指がキューブに触れていない | まだ触れていない |
| 1 | 右グリッパーの指がキューブに触れている | 触れた |
| 2 | 右グリッパーの指が触れていて、キューブがテーブルに触れていない | 持ち上げた |
| 3 | 左グリッパーの指がキューブに触れている（テーブルとの接触は問わない） | 受け渡しを試みた |
| 4 | 左グリッパーの指が触れていて、キューブがテーブルに触れていない | **成功** |

- 報酬が 4 になった時点でエピソードは終了します（`terminated`）。4 にならなければ、最大ステップ数（400）で打ち切られます（`truncated`）。
- 成功の条件は「左で持ち上げていること」だけで、右グリッパーが離れているかは問いません。
- 報酬は瞬間の値なので、落とせば下がります。そこで評価では、**エピソード中の最大報酬（`max_reward`）** を「どの段階まで進んだか」の指標にしています。

## 失敗の型の定義

失敗したエピソード（`max_reward` < 4）を、最大報酬で 4 つの型に分けます。名前は「最大報酬 r の次の段階 r+1 に進めなかった」ことを表しています。

| 失敗の型（`failure_type`） | 最大報酬 | 意味 |
|---|---|---|
| `no_touch` | 0 | 右グリッパーがキューブに一度も触れなかった |
| `not_lifted` | 1 | 触れたが、持ち上げられなかった |
| `not_transferred` | 2 | 持ち上げたが、左グリッパーが一度も触れなかった（受け渡しに入れなかった） |
| `transfer_failed` | 3 | 左グリッパーが触れたが、左で持ち上げた状態にならなかった |

成功したエピソードの `failure_type` は `null` です。

## results.json の項目

| 項目 | 内容 |
|---|---|
| `config` | 評価に使った設定（チェックポイント、エピソード数、シード、最大ステップ数、temporal ensembling など）。値はすべて文字列で保存 |
| `success_rate` | 成功したエピソードの割合（0〜1） |
| `reached` | 各段階**以上**まで到達したエピソードの割合（`max_reward` ≥ 1, 2, 3, 4）。キーは `touched` / `lifted` / `transfer attempted` / `success` |
| `failure_types` | 失敗したエピソードの本数を型ごとに数えたもの（上の表の 4 つ） |
| `predict_ms` | `predict_chunk` 1回にかかった時間の平均・中央値（ミリ秒）と呼び出し回数。50Hz 制御の 1 ステップ（20ms）に収まるかを見るため |
| `sampler` | Diffusion のときだけ。実際に使ったサンプラーと推論ステップ数 |
| `episodes` | エピソードごとの結果（下の表） |

`episodes` の各要素:

| 項目 | 内容 |
|---|---|
| `seed` | リセットに使ったシード。エピソード i はシード `seed + i`。キューブの初期位置がシードで決まるので、同じシードなら別のポリシーと同じ初期配置で比べられる |
| `success` | 成功したか（`max_reward` == 4） |
| `max_reward` | エピソード中の最大報酬（0〜4） |
| `steps` | 実行したステップ数。成功ならその時点で終わるので 400 未満、失敗なら 400 |
| `failure_type` | 失敗の型（成功なら `null`） |

`reached` と `failure_types` の関係: `reached` は累積の割合、`failure_types` は各段階で止まった本数です。
例えば 50 本のうち `touched` 0.96 / `lifted` 0.84 なら、`not_lifted` は (0.96 − 0.84) × 50 = 6 本になります。

## 動画

`videos/` に次の動画を保存します。フレームの左上に、シード・ステップ数・その時点までの最大報酬が表示されます。

| 対象 | ファイル名の例 |
|---|---|
| 先頭 `--num-videos` 本（既定 5 本）のエピソード | `ep000_seed0_success.mp4` / `ep002_seed2_fail_not_lifted.mp4` |
| 失敗したエピソードすべて（`--save-failed-videos`、既定で有効） | `ep039_seed39_fail_no_touch.mp4` |

失敗した動画のファイル名の末尾は失敗の型なので、型ごとにまとめて見られます（例: `ls videos/*not_transferred*`）。
失敗の動画を保存しないときは `--no-save-failed-videos` を付けます。失敗を残すために全エピソードを記録するので、付けたほうが少し速くなります。
